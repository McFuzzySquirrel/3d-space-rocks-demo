# Key Learnings
Technical insights
- Babylon modular import correctness and TS `verbatimModuleSyntax` type-only imports are common integration pitfalls.
- FollowCamera setup is best isolated in a dedicated module with a replaceable target contract.
- Fixed-step updates keep movement behavior stable prior to full physics.
Prompting insights
- Specialist delegation is effective when prompts contain strict phase boundaries and explicit out-of-scope constraints.
- Iteration quality improves when each delegation includes validation requirements.
Tooling insights
- `python3 scripts/adr-db.py sync` should run at session boundaries.
- EJS hooks can warn on missing journey artifacts without blocking delivery unless explicitly enforced.

# If Repeating This Work
Do this:
- Initialize EJS, then run a tech-currency check before Phase 1.
- Delegate by phase with clear ownership and explicit validation gates.
- Commit at logical milestones to preserve recoverable state.
Avoid this:
- Mixing Phase 2 physics into Phase 1 implementation.
- Deferring journey updates until the end.
Watch out for:
- Babylon import/API drift across major versions.
- Hidden type regressions from non-type-only imports under strict TS settings.

# Future Agent Guidance
Prefer:
- Phase-locked execution with clear owner handoffs.
- Typed contracts and modular bootstrap boundaries.
- Recording decisions as they happen, not post-hoc.
Avoid:
- Scope bleed between scene setup, gameplay logic, and physics.
- Skipping ADR evaluation when process boundaries are changed.
