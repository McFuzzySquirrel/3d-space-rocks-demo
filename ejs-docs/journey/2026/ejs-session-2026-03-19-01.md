# Key Learnings

Technical insights:
- Babylon.js `CreatePolyhedron` with `type: 0/1/2` produces tetrahedron, octahedron, and dodecahedron respectively — useful for procedural shape variety without external assets.
- Scaling vertex displacement noise proportionally to `baseRadius` (e.g., `baseRadius * 0.12`) rather than using fixed noise amplitudes ensures consistent surface roughness across all asteroid sizes.
- Keeping physics colliders as `SphereImpostor` regardless of visual geometry avoids physics instability from non-convex shapes, while still providing full visual variety.

Prompting insights:
- When a user reports an incorrect behaviour ("ends game rather than removing a life"), always trace from the user-visible effect back to the exact call site before editing — in this case `takeDamage(this._player.getLives())` was obvious once read.
- Explaining mechanics in plain terms ("the queue is built once and drains to empty") resolves player confusion without requiring code changes.

Tooling insights:
- `npm run build` (tsc + vite) is a reliable one-command validation for all TypeScript + bundler correctness checks together.
- Reading the full PRD before updating ensures no requirement IDs are accidentally removed or gaps are introduced during targeted edits.

# If Repeating This Work

Do this:
- Always read `takeDamage` call sites when debugging unexpected game-over-on-first-hit bugs — the damage amount parameter is the most common culprit.
- Keep physics impostors as sphere/box primitives even when visual meshes are complex polyhedra.
- Update the PRD immediately after each iteration cycle, not at the end of the project.

Avoid this:
- Scaling vertex noise by fixed absolute values across differently-sized asteroid meshes — proportional scaling is required.
- Creating a new `MeshFactory` function per shape variant; a single `buildAsteroidBaseShape` switch with a random selector is cleaner and easier to extend.

Watch out for:
- `CreatePolyhedron` requires `size` not `radius` — easy mismatch with `CreateIcoSphere` signature.
- `CreateCylinder` tessellation values below 5 look too angular for believable rocks; 5–8 is the practical range.

# Future Agent Guidance

Prefer:
- Single-function shape pickers with a random variant index rather than multiple exported mesh builders for similar entity types.
- Proportional noise displacement (percentage of base radius) for procedural mesh deformation across variable-size entities.
- Retaining existing physics impostor types when changing visual mesh geometry to avoid physics regression.
- Updating the PRD at the end of each gameplay iteration session to keep it as the authoritative spec.

Avoid:
- Mixing physics impostor types (e.g., BoxImpostor for box-shaped asteroids) without thorough testing — sphere is safe and predictable.
- Leaving `takeDamage` callers with hardcoded life counts; always pass `1` (or a config-driven value) unless you specifically intend instant death.
